# ТЗ: конвертер «Yangi alifbo» для esys.pro

Ты работаешь в репозитории сайта esys.pro (веб-студия Evolution Systems, Ташкент). Нужно добавить на сайт бесплатный онлайн-инструмент: конвертер текста на новый узбекский латинский алфавит. Закон об обновлении алфавита подписан 21.10.2026 (ЗРУ O‘RQ-1184, https://www.lex.uz/uz/docs/8548754). Инструмент — SEO-магнит и лид-генератор для услуги «перевод сайта на новый алфавит».

3. Коротко опиши план (какие файлы создашь или изменишь) и только потом реализуй.
4. Ничего не ломай: существующие страницы, стили и тесты должны работать как раньше.

## 1. Что меняется в алфавите

Было: 29 элементов (в том числе oʻ, gʻ, sh, ch, ng) + tutuq belgisi. Стало: 28 букв + 1 знак (tutuq belgisi).

| Старая латиница | Новая латиница |
|---|---|
| Oʻ oʻ | Ö ö |
| Gʻ gʻ | Ğ ğ |
| Sh sh | Ş ş |
| Ch ch | Ç ç |
| ng | ng (больше не считается отдельным элементом алфавита, в тексте не меняется) |
| ʼ (tutuq belgisi) | ʼ (остаётся) |

Всю таблицу соответствий держи в одном конфиг-файле (например `alphabet-map.ts`), чтобы её можно было поправить без изменения логики. Символ апострофа в новом алфавите вынеси в константу (по умолчанию U+02BC `ʼ`). До начала работы сверь символ с текстом закона на lex.uz и отметь результат в отчёте.

## 2. Режимы конвертации (v1)

1. **Старая латиница → новая латиница** (основной режим, по умолчанию).
2. **Кириллица → новая латиница.**
3. **Новая латиница → старая латиница** (обратный, для совместимости).
4. **Автоопределение:** если в тексте преобладает кириллица, включай режим 2, иначе режим 1. Пользователь может переключить вручную.

Вывод в кириллицу в v1 не делаем (там неоднозначности с е/йе и ц/тс); заложи архитектуру так, чтобы его можно было добавить позже.

## 3. Правила (самое важное, тут нужна точность)

### 3.1 Старая латиница → новая

- Нормализуй все способы, которыми люди пишут знак у oʻ/gʻ: `'` (U+0027), `‘` (U+2018), `’` (U+2019), `` ` `` (U+0060), `ʻ` (U+02BB), `´` (U+00B4).
- **U+02BC `ʼ` (символ нового апострофа) не считается знаком oʻ/gʻ.** Это tutuq, его не трогай. Иначе ломается идемпотентность: из кириллицы `о+ъ` получится `oʼ`, и повторный прогон превратит его в `Ö`. Исключение: `moʻʼjiza` (U+02BB, затем U+02BC) — первый знак буква, второй tutuq.
- **o/g + знак → Ö/Ğ**, в том числе в конце слова (`tog'` → `toğ`, `bog'` → `boğ`).
- **Знак после любой другой буквы — tutuq belgisi, только если сразу после него идёт буква** (`ma'no` → `maʼno`). Если после знака не буква (пробел, пунктуация, конец строки), это кавычка: не меняй (`'salom'` → `'salom'`).
- Двойной знак после o/g: первый — часть буквы, второй — tutuq (`mo''jiza` → `möʼjiza`, `moʻʼjiza` → `möʼjiza`).
- **sh → ş, ch → ç** всегда, кроме случаев, где s и h разделены апострофом (`Is'hoq`, `as'hob`): их оставляй как `s` + `ʼ` + `h`. Поведение в этих случаях вынеси в настройку; позже уточним по орфографическим правилам.
- **Регистр:** `Sh`/`SH` → `Ş`, `sh` → `ş`, `Oʻ`/`O'` → `Ö`, в тексте КАПСОМ `O'ZBEKISTON` → `ÖZBEKISTON`. Смешанный `sH` → `ş` (по первой букве).
- Не трогай: URL, e-mail, хештеги и упоминания (@...), текст внутри обратных кавычек `` `код` ``. Сделай это опцией «Не изменять ссылки и код» (включена по умолчанию).
- **Чужие слова в латинском тексте** (бренды, английские слова и имена): `Shopify`, `WhatsApp`, `Tech`, `don't`, `O'Brien`. Механизм:
  - словарь исключений `exceptions.json` (слово → правильная форма или «не менять»). Применяется до общих правил, без учёта регистра при поиске, с сохранением регистра в выводе. Заполни стартовым списком частых брендов и IT-терминов (Shopify, WhatsApp, Chrome, Shell, Tech, Cache, Push, Flash, Chat и т.п.);
  - опция «Не изменять слова на английском» (выключена по умолчанию): простая эвристика по словарю частых английских слов. Если сложно — оставь `TODO`, но словарь исключений обязателен.

### 3.2 Кириллица → новая латиница

| Кир. | Лат. | Кир. | Лат. |
|---|---|---|---|
| а | a | п | p |
| б | b | р | r |
| в | v | с | s |
| г | g | т | t |
| ғ | ğ | у | u |
| д | d | ў | ö |
| е | e / **ye** (в начале слова, после гласной, после ъ/ь) | ф | f |
| ё | yo | х | x |
| ж | j | ҳ | h |
| з | z | ц | **s** (в начале слова и после согласной) / **ts** (после гласной) |
| и | i | ч | ç |
| й | y | ш | ş |
| к | k | ъ | ʼ, но **удалить** перед е/ё/ю/я (см. ниже) |
| қ | q | ь | (удалить) |
| л | l | э | e |
| м | m | ю | yu |
| н | n | я | ya |
| о | o | | |

- **ъ перед е/ё/ю/я** (русские заимствования) не пишется; е после него всё равно даёт `ye`: `объект` → `obyekt`, `съезд` → `syezd`. В остальных случаях ъ → константа апострофа (`маъно` → `maʼno`).
- **Регистр:** `Ш` → `Ş`. Буквы, которые дают две латинские (`Ё`, `Ю`, `Я`, `Е`→`Ye`, `Ц`→`Ts`), в слове КАПСОМ пишутся капсом целиком (`ЁЗ` → `YOZ`, `МИЛИЦИЯ` → `MILITSIYA`), иначе только первая заглавная (`Ёз` → `Yoz`). Слово из одной заглавной буквы считай капсом, если соседнее слово тоже капсом.

### 3.3 Предупреждения

Если конвертер встретил неоднозначный случай, подсвечивай это место в результате и показывай подсказку «Проверьте написание». Текст при этом всё равно конвертируется. Неоднозначные случаи:

- знак после o/g, за которым идёт ещё один знак;
- `s'h`;
- o/g + знак в конце слова внутри кавычек (`'bog'` — буква или закрывающая кавычка?);
- слово, где одновременно есть латиница и кириллица;
- слово, похожее на английское или бренд, но которого нет в `exceptions.json` (если включена эвристика).

## 4. Архитектура

- Вся конвертация — чистые функции в отдельном модуле без зависимостей от DOM и Nuxt: `convert(text, { mode, keepLinks, ... }) → { result, warnings[], replacements }`.
- Модуль пиши на чистом TypeScript без алиасов Nuxt (`~`, `#imports`) и автоимпортов, чтобы его запускал `node --experimental-strip-types` (в том числе синтаксис, который поддерживает strip-types: без `enum` и `namespace`). Импорт JSON — через `import ... with { type: 'json' }` или храни словари в `.ts`.
- Работает полностью в браузере: текст не отправляется на сервер. Напиши об этом на странице («Matn serverga yuborilmaydi»).
- Без тяжёлых библиотек. Добавленный JS для страницы — до ~30 КБ gzip. Не подключай на этой странице gsap, three и тяжёлые анимации.
- Модуль пригоден для повторного использования (позже сделаем из него API, Telegram-бота и браузерное расширение), поэтому никакой логики, завязанной на конкретную страницу, внутри него нет.

## 5. Интерфейс

- Две панели: исходный текст и результат (на мобильных одна под другой).
- Переключатель режима + автоопределение, кнопка «поменять направление».
- Конвертация на лету при вводе (debounce ~150 мс), плюс работает вставка большого текста (до 100 000 символов без подвисания).
- Кнопки: «Копировать результат» (с подтверждением «Скопировано»), «Очистить», «Скачать .txt», «Загрузить .txt».
- Счётчик символов и количество сделанных замен.
- Подсветка изменённых букв в результате (можно отключить). Если текст длиннее ~20 000 символов, автоматически отключай подсветку (с пометкой в интерфейсе), чтобы не рендерить десятки тысяч `<span>`.
- Панель быстрых кнопок для ввода новых букв в любое поле: `Ö ö Ğ ğ Ş ş Ç ç ʼ`.
- Доступность: подписи у полей, работа с клавиатуры, aria-live для сообщения «Скопировано», достаточный контраст. Стили — тёмная тема сайта (светлой нет).

## 8. Аналитика

Отправляй события через `useTrackEvent`: `converter_convert` (режим и длина текста бакетами: `<100`, `100–1k`, `1k–10k`, `>10k`; без самого текста и без точной длины), `converter_copy`, `converter_download`, `converter_cta_click`. `converter_convert` шли не на каждый ввод, а не чаще раза в несколько секунд или по завершении ввода.
